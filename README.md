# Salesforce MFA Check

`audit_mfa.py` audits a Salesforce org that is already authenticated in the Salesforce CLI and reports the settings most relevant to the June/July 2026 MFA enforcement waves.

## What it checks

- Org-wide direct UI MFA enforcement from `Security.settings`
- Availability of phishing-resistant MFA methods in the org:
  - built-in authenticators
  - physical security keys / U2F / WebAuthn
- Internal users who are in scope for privileged-user phishing-resistant MFA because of:
  - `System Administrator` profile
  - `Modify All Data`
  - `View All Data`
  - `Customize Application`
  - `Author Apex`
- Users with permission-based UI MFA assignments
- Users with bypass / waiver assignments (`PermissionsBypassMFAForUiLogins`)
- Presence of SAML SSO configs that require separate IdP AMR/ACR validation
- A `LoginHistory` sample of the most recent 100 logins, including `AuthMethodReference` values when exposed, with observed AMR codes classified as standard MFA, phishing-resistant MFA, weak/no MFA, or unrecognized
- A `VerificationHistory` sample for non-SSO logins, with observed Salesforce verification methods classified as standard MFA, phishing-resistant MFA, or weak/recovery methods

## What it does not fully automate

- Whether every SSO login path sends the correct AMR / ACR signals from the IdP in all scenarios
- Whether each user has already registered a compliant MFA method

Those are called out in the report under `manualReview`, even though the report now includes a sampled `SSO Signal History` section from recent `LoginHistory` rows.

## Prerequisites

The Salesforce CLI (`sf`) is the primary dependency. At startup the script
confirms `sf` is installed (exiting if it is not) and warns if the CLI is
below the known-good minimum version.

## Building a standalone macOS executable

You can package the auditor as a single self-contained binary so it can run on
machines without a Python environment (the Salesforce CLI is still required at
run time — it is not bundled).

Use the provided build script instead of calling PyInstaller directly:

```bash
./build.sh
```

This runs a clean PyInstaller `--onefile` build and then **ad-hoc signs** the
result, producing `dist/salesforce-mfa-audit`.

One-time setup (if needed):

```bash
python3 -m pip install pyinstaller
```

Optional overrides via environment variables:

```bash
APP_NAME=my-mfa-tool ./build.sh          # change the output binary name
TARGET_ARCH=universal2 ./build.sh        # build a universal (arm64 + x86_64) binary
```

> Note: after switching to `./build.sh`, you no longer run the raw
> `pyinstaller audit_mfa.py` command — `build.sh` performs the build and the
> signing in one step.

### Distribution / macOS Gatekeeper

The binary is **ad-hoc signed**, not signed with an Apple Developer ID and not
notarized. What that means:

- It runs fine on the machine where you built it.
- On **Apple Silicon** the ad-hoc signature is what lets it execute at all
  (an unsigned binary is killed by the OS). Re-sign if you modify the binary.
- Ad-hoc signing does **not** clear Gatekeeper's *quarantine*. When the file is
  copied to another Mac via browser, email, AirDrop, or an unzipped download, it
  gains the `com.apple.quarantine` attribute and is blocked on first launch.

To run it on another Mac, clear quarantine there once:

```bash
xattr -dr com.apple.quarantine /path/to/salesforce-mfa-audit
chmod +x /path/to/salesforce-mfa-audit
```

Alternatively, after the first blocked launch, approve it under
**System Settings → Privacy & Security → Open Anyway**. Transferring via
`git clone`/`scp`/an internal share often avoids the quarantine attribute
altogether.

For friction-free distribution (no `xattr` step), sign with an **Apple
Developer ID Application** certificate and notarize with `xcrun notarytool`
+ `xcrun stapler`.

## Usage

Simplest run (no flags):

```bash
python3 audit_mfa.py
```

With no flags the script will:
- confirm the Salesforce CLI is available,
- if no `--org` is given, list authenticated orgs from `sf org list` and prompt you to pick one (defaulting to the CLI default org),
- generate a Markdown report by default (named `<org>-mfa-report.md`),
- ask whether you also want an HTML report, and if so, whether to open it.

Progress lines are written to stderr while it runs, for example:

```text
[mfa-audit] Salesforce CLI confirmed (v2.128.5)
[mfa-audit] Loading org connection details
```

Target a specific org (skips the selection prompt):

```bash
python3 audit_mfa.py --org MyOrg
```

### Output options

Markdown is generated by default. To choose the file name:

```bash
python3 audit_mfa.py --org MyOrg --markdown-file mfa-report.md
```

To suppress the Markdown report entirely:

```bash
python3 audit_mfa.py --org MyOrg --no-markdown
```

When a Markdown report is generated, the script also writes sibling scatterplot
image assets and a same-name `.html` report (with the SVG embedded inline for
browser viewing). After the run, you are asked whether to open that HTML file.

Write the HTML report directly (to a specific path):

```bash
python3 audit_mfa.py --org MyOrg --html-file mfa-report.html
```

JSON output (printed to stdout):

```bash
python3 audit_mfa.py --org MyOrg --json
```

Write JSON to a file:

```bash
python3 audit_mfa.py --org MyOrg --output mfa-report.json
```

For very large orgs where the fuller user analysis times out, use sampled mode:

```bash
python3 audit_mfa.py --org MyOrg --large-org-sample
```

> Note: the interactive org picker and the end-of-run "open HTML" prompt require
> a terminal (TTY). In non-interactive contexts (CI, cron) pass `--org`; the
> Markdown and sibling HTML reports are still written, and the open prompt is
> simply skipped.

## 2026 enforcement dates reviewed

- Sandbox:
  - all UI logins MFA starts June 22, 2026
  - privileged users phishing-resistant MFA starts June 22, 2026
- Production:
  - privileged users phishing-resistant MFA starts July 1, 2026
  - all UI logins MFA starts July 20, 2026

Salesforce rolled these changes out in waves from those dates, so treat them as start windows rather than a single instant cutoff.
